## Более точное объяснение «worker returned no response»

Предварительный прогрев Kokoro завершился ошибкой в 18:02:24, до запуска
Omni. Windows Application / Event ID 1000 в 18:02:20.574 фиксирует падение
python.exe, PID 0x7BEC, exception 0xc0000005, модуль
`Runtime/Python/reranker/.venv/Lib/site-packages/tokenizers/tokenizers.cp312-win_amd64.pyd`.
WER ID 1001 появился в 18:02:24.302, report ID
`4b9376e2-364e-4c7d-8e9e-36ce66f7c935`.

Повторная попытка речи вернула no response в 18:04:12.805. Перед ней Windows
зарегистрировала падение python.exe в 18:04:09.159, PID 0x15E8,
exception 0xc0000005, модуль unknown; WER report ID
`3e675229-59ae-4e6e-b795-10c6dceb19c4`.

Аналогичная пара в предыдущем запуске: 17:57:01 — tokenizers, 17:57:55 —
unknown, обе с 0xc0000005; приложение записало ошибки прогрева в 17:57:05
и речи в 17:57:59. В 17:54:00 также зарегистрировано падение в tokenizers,
перед no response в 17:54:04.

Это сильная временная и модульная связь с Kokoro: её runtime-service запускает
Python именно из `Runtime/Python/reranker/.venv`; в момент нового прогрева
Omni ещё не запущена. Полная командная строка упавшего дочернего процесса
в приведённых событиях не сохранена, поэтому это не трассировка стека Kokoro.

## Выводы и границы

- Сообщение «нет ответа» скрывает аварийное завершение нативного процесса,
  а не просто неудачный текст модели. Python traceback при таком выходе
  может отсутствовать.
- Несколько сбоев локализованы Windows в tokenizers. Это место проявления,
  не доказательство первопричины: несовместимость пакетов, ошибка библиотеки,
  повреждение памяти либо иная причина требуют отдельной проверки.
- Успешная русская речь уже была в этой же версии. Постоянная невозможность
  русского синтеза и зависимость падения от размера картинки не подтверждены.
- Следующая диагностика должна сохранять PID, команду запуска, код выхода,
  stderr и версионный состав окружения до его изменения. Не следует менять
  модель или массово обновлять зависимости на основании одного имени модуля.
- Настройки текста и JSON-контракт — отдельная проблема; EOS в этих попытках
  работает. Программа, модели и системные настройки при проверке не изменялись.

Источники: указанный Core JSONL, соответствующий session.json,
`%LOCALAPPDATA%/AI_HUB/Diagnostics/kokoro-metrics.jsonl`, Windows Application
Event IDs 1000/1001 и WER Report.wer для приведённых report IDs. Сырые WER
и дампы не копировались в репозиторий во избежание публикации памяти процессов.
