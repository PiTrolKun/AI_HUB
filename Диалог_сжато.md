# Диалог сжато — AI_HUB

Дата фиксации: 2026-05-30

## Краткая история

Пользователь начал новый проект AI_HUB и передал итоговую концепцию русскоязычного локального AI-хаба для Windows 11.

После этого были добавлены инструкции для Codex в папку `Инструкции`:

- `AGENTS.md`
- `CODEX.md`

Codex прочитал инструкции и зафиксировал важные правила работы:

- пользователь не программист;
- перед новой задачей нужно сверять актуальные инструкции и контекст;
- перед крупной реализацией нужен ТЗ-файл;
- перед изменением существующих файлов нужен backup;
- проект ориентирован на C# / .NET / WPF;
- проверяемость и понятный откат важны с самого начала.

## Текущая задача

Создать полный стартовый скелет проекта:

- служебные документы;
- документацию проекта;
- папки для ТЗ, backup, исходников, тестов и инструментов;
- runtime-папки для моделей, результатов, backends, кэша, логов и RAG;
- README-файлы в важных папках.

## Ближайший следующий шаг после этой задачи

Подготовить ТЗ на первый MVP: WPF-каркас приложения в стиле проводника.

## 2026-05-30 — подготовка .NET/WPF окружения

Пользователь спросил, согласен ли Codex с языком программирования из идеи, и попросил проверить зависимости.

Codex подтвердил, что `C# / .NET / WPF` подходит проекту, потому что нужен нативный Windows 11 интерфейс в стиле проводника и глубокая работа с Windows.

Проверка показала:

- `git` установлен;
- `winget` установлен;
- PowerShell 7 установлен;
- .NET runtime 8 был установлен;
- .NET SDK отсутствовал.

Установлен Microsoft .NET SDK 10.0.300 через winget. После установки проверено, что WPF-шаблон доступен, а временный WPF-проект на `net10.0-windows` успешно собирается.

## 2026-05-30 — правила версий, архивации ТЗ и истории

Пользователь попросил добавить в правила строгую нумерацию версий и обязательную публикацию актуального состояния проекта в GitHub при переносе ТЗ в архив.

Codex обновил `AGENTS.md` и `CODEX.md`, добавил правило версионирования и правило GitHub-публикации при архивации ТЗ.

ТЗ подготовки .NET/WPF окружения перенесено в архив. По прямому указанию пользователя повторный push в GitHub не выполнялся, потому что заготовка проекта была опубликована прямо перед этим.

После замечания пользователя выявлено, что запись о действии не была добавлена в историю сразу. Добавляется новое правило: после каждого выполненного действия делать краткую запись в истории проекта, с датой, сутью действия, проверками, commit/push и исключениями из правил.
