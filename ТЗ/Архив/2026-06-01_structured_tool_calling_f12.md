# ТЗ: structured tool-calling для F12

Дата: 2026-06-01

## Цель

Проверить и внедрить официальный structured tool-calling для связки `llama-server + Qwen3`, чтобы debug-ядро F12 вызывало инструменты через формат `tools` / `tool_calls`, а не через самодельный текстовый протокол вида `web_search: ...`.

## Почему это нужно

Текущий F12 tool-agent просит модель писать команды инструментов обычным текстом. На практике Qwen3 иногда пишет намерение вроде "я вызываю инструмент", но не выдаёт строгую строку команды. Из-за этого появляются циклы, тайм-ауты, ложные финальные ответы и попытки скачать выдуманные URL.

Документация llama.cpp и Qwen описывает более правильный путь: передавать список инструментов в запросе как `tools`, получать от модели структурный `message.tool_calls`, выполнять инструмент и возвращать результат обратно как `role: tool`.

## Этап 1 — исследование

- Проверить, поддерживает ли текущий `llama-server b9442` настоящий OpenAI-compatible tool calling.
- Отправить тестовый `/v1/chat/completions` запрос с `tools`.
- Проверить, возвращает ли Qwen3:
  - `message.tool_calls`;
  - корректное имя функции;
  - корректные JSON-аргументы;
  - нормальный `finish_reason`.
- Отдельно проверить влияние:
  - `--jinja`;
  - `--reasoning off`;
  - текущего GGUF chat template;
  - простых и сложных JSON-схем.

## Этап 2 — архитектура

Если `tool_calls` работают:

- добавить в `LlamaServerRuntimeService` поддержку structured tools;
- описать инструменты AI HUB как функции:
  - `web_search`;
  - `web_research`;
  - `web_read`;
  - `web_download`;
  - `inventory`;
  - `task_plan`;
  - `hf_find_model`;
  - `hf_model_files`;
- возвращать результат инструмента модели как `role: tool`;
- оставить старый текстовый протокол только как fallback.

Если `tool_calls` работают нестабильно:

- зафиксировать причину;
- оставить безопасный fallback;
- отдельно рассмотреть Qwen-Agent, Ollama tool calling, grammar/JSON schema output или более строгий текстовый протокол.

## Этап 3 — F12 UX

- Не заставлять обычные вопросы проходить через tool-agent.
- Разделить поведение:
  - прямые команды инструментов выполняются сразу;
  - обычные вопросы идут обычным чатом;
  - задачи, требующие инструментов, используют structured tool-calling.
- В логах показывать:
  - какой tool вызван;
  - какие аргументы переданы;
  - какой результат вернулся;
  - когда использован fallback.

## Этап 4 — безопасность

- `web_download` разрешать только:
  - по прямой ссылке пользователя;
  - по URL, найденному инструментом;
  - по URL из Hugging Face provider.
- Не принимать выдуманные URL от модели как основание для скачивания.
- Логировать все tool-вызовы и результаты.
- Не давать модели прямой shell/файловый доступ.

  - `web_search`;
  - `web_research`;
  - попытка скачать выдуманный URL должна блокироваться или уходить в безопасный fallback;
  - скачивание подтверждённого URL должно проходить.

## Не входит

- Не менять основной пользовательский сценарий `Начать работу`.
- Не делать установщик без отдельной команды.
- Не подключать платные API.
- Не давать модели прямой shell/файловый доступ.
