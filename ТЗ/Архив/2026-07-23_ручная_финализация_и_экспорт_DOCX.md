# ТЗ: ручная финализация executor-сессии и экспорт DOCX

Дата начала: 2026-07-23
Статус: выполнено и принято пользователем 2026-07-23
Зависимость: `2026-07-23_дерево_сессии_и_содержательный_результат.md`

## 1. Цель

Завершить пользовательский контур «Режима неопределённости»: исполнитель может рекомендовать завершение, но только пользователь решает, продолжать работу, завершить её без итогового документа, показать полный итог в AI HUB или экспортировать его в DOCX.

## 2. Принцип управления

- Практическое уточнение остаётся вторым и последним этапом работы исполнителя.
- Рекомендация завершения не является новым этапом, автоматическим финалом или сохранением.
- Исполнитель не может завершить сессию, сохранить файл или вызвать интерфейсную команду.
- Кнопка `Завершить сессию` доступна пользователю в любой момент.
- Итоговый документ создаётся только отдельной программной командой.

## 3. Сигнал готовности исполнителя

- В executor-контракт добавляется действие `suggest_finalization`.
- Готовность результата отделяется от наличия следующего полезного вопроса обязательным признаком `canFinalize`.
- `canFinalize = true` означает, что текущий результат уже самодостаточен и может быть выдан, даже если исполнитель предлагает ещё одно необязательное улучшение через `ask_user`.
- При `canFinalize = true` исполнитель обязан вернуть краткую причину готовности, актуальный пересказ, содержательный рабочий фрагмент и пустой список критических пробелов.
- Сигнал разрешён только на практическом этапе после подтверждения постановки.
- Для сигнала исполнитель возвращает краткую причину готовности, актуальный пересказ и содержательный рабочий фрагмент; критические пробелы должны отсутствовать.
- Вопрос и модельные варианты завершения при таком действии не требуются.
- Если новый ответ снова делает результат существенно неполным, исполнитель возвращает `canFinalize = false`, и кнопка возвращается наверх. Необязательное продолжение может сохранять `canFinalize = true`.
- Обычные ответы с вариантами `Сохранить`, `Экспортировать`, `Завершить сессию`, `Выдать результат` и смысловыми аналогами отклоняются программой и проходят repair.

## 4. Перемещение кнопки

- Во время обычной работы кнопка завершения находится в верхней части панели исполнителя.
- При `canFinalize = true` верхняя кнопка плавно исчезает, а её копия появляется в нижней панели рядом с вариантами ответа.
- Нижняя кнопка получает короткую ненавязчивую акцентную анимацию и затем остаётся статичной.
- Обе визуальные кнопки вызывают одну программную команду.
- После продолжения работы нижняя кнопка скрывается, верхняя возвращается.

## 5. Диалог завершения

По нажатию `Завершить сессию` открывается модальное окно.

Первый выбор:

- `Завершить без сохранения` — закрыть executor-сессию без создания итогового документа;
- `Сделать экспорт` — перейти к выбору способа получения результата;
- закрытие окна или `Вернуться` — продолжить сессию.

Второй выбор:

- `Прямой вывод` — создать полный финальный документ и открыть его в отдельном окне;
- `Экспорт в DOCX` — выбрать путь, создать тот же финальный документ и сохранить его в файл;
- `Назад` — вернуться к первому выбору.

Технический JSONL-журнал сохраняется при любом варианте.

## 6. Формирование финального документа

- Предварительная кнопка `Выдать результат` продолжает создавать не завершающий сессию снимок.
- Финальный документ формируется отдельным запросом `[AI_HUB_FINAL_RESULT_REQUEST]`.
- Источник финала: подтверждённая постановка, активная ветвь дерева, решения пользователя, содержательные рабочие фрагменты, результаты инструментов, источники и ограничения.
- Служебные фразы о готовности, команды интерфейса и метаописания не должны подменять результат.
- Экранный вывод и DOCX используют один и тот же экземпляр финального Markdown.
- Сессия завершается только после успешного создания и показа либо сохранения результата.
- При ошибке генерации, отмене выбора файла или ошибке экспорта сессия остаётся активной.

## 7. DOCX

- Первая версия поддерживает один формат: `.docx`.
- Для формирования используется официальная библиотека Open XML SDK.
- Поддерживаются заголовки, абзацы, маркированные и нумерованные списки, простой полужирный текст и переносы.
- Файл создаётся только по выбранному пользователем пути.
- Автоматический запуск Word или другого внешнего приложения не выполняется.

## 8. Журналирование и дерево

- Журналируются рекомендация завершения, открытие/отмена диалога, выбранный способ, запрос финального документа, успешное создание, путь экспорта без содержимого файла, ошибка и причина завершения.
- Финальный документ получает отдельную версию и пометку `IsFinal`.
- Финальная версия добавляется в дерево как результат активной ветви до остановки executor-сессии.

## 9. Локализация и доступность

- Все новые видимые строки добавляются в `ru.json` и `en.json`.
- Кнопки и диалог доступны с клавиатуры.
- Опасное действие `Завершить без сохранения` визуально не конкурирует с основным действием формирования результата.
- Анимация не должна менять размеры рабочей сетки или создавать прокрутку.

## 10. Что не входит

- PDF, Markdown, HTML и другие форматы экспорта.
- Экспорт файлов, приложенных пользователем к будущим сценариям.
- Автоматическое открытие экспортированного DOCX.
- Автоматическое завершение по решению модели.
- Скачивание новых AI-моделей.
- Сборка установщика.
- Автоматическое управление UI для ручного теста.

## 11. Риски

- Слабая модель может ошибочно рекомендовать завершение: пользовательская кнопка и ручное решение остаются источником истины.
- Модель может маскировать интерфейсные команды под варианты: требуется отдельная семантическая проверка.
- Ошибка экспорта не должна уничтожать сессию или уже созданный результат.
- Новый NuGet-пакет должен быть зафиксирован в реестре и уведомлениях о сторонних компонентах.

## 12. Проверки

- Парсер принимает `suggest_finalization` только в допустимой форме.
- Семантическая политика отклоняет модельные команды сохранения/завершения.
- DOCX открывается как корректный ZIP/Open XML-пакет и содержит текст результата.
- Debug/Release build без новых предупреждений.
- Все автоматические тесты проходят.
- Форматирование, UTF-8 scanner, локализации и `git diff --check` проходят.
- Новые модели не скачиваются; установщик не собирается.

## 13. Критерии приёмки

- Исполнитель может рекомендовать завершение, но не завершает работу самостоятельно.
- Исполнитель может одновременно задать необязательный вопрос и отметить, что уже накопленный результат пригоден к выдаче.
- Кнопка визуально переезжает в нижнюю панель без скачка layout.
- Завершение без результата требует явного выбора.
- Прямой вывод открывает полный финальный документ.
- Экспорт создаёт корректный DOCX по выбранному пути.
- Прямой вывод и DOCX строятся из одного финального результата.
- Любая ошибка до успешной выдачи результата оставляет executor-сессию активной.
