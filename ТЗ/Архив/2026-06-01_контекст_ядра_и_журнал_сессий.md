# ТЗ: контекст ядра и журнал сессий

Дата: 2026-06-01

## Цель

Научить AI HUB передавать основному AI-ядру скрытый служебный контекст и сохранять историю работы так, чтобы пользователь мог возвращаться к начатому, а сбой ПК не уничтожал весь диалог.

## Решения

- Текущая дата, время, часовой пояс и UTC-смещение берутся локально из Windows перед запросом к модели.
- Примерное местоположение определяется автоматически по IP и сохраняется в будущем профиле пользователя.
- Ручное местоположение из профиля, когда появится, имеет приоритет над IP.
- Fallback из Windows-региона не использовать: язык/регион системы не равны фактическому месту пользователя.
- Служебный контекст не показывать в обычном чате.
- 1 запуск программы = 1 общая сессия ядра = 1 файл `jsonl`.
- У каждой задачи/работы позже будут свои файлы на уровне задачи.
- Отладочное окно `F12` пишет в отдельную debug-зону и не засоряет обычные файлы ядра.

## Хранение

Если настроена папка результатов, рабочие файлы пишутся в первый адрес результатов:

```text
<Папка результатов>\AI_HUB\Core\Sessions\
<Папка результатов>\AI_HUB\Tasks\
<Папка результатов>\AI_HUB\Tools\
<Папка результатов>\AI_HUB\Debug\ModelTester\
```

Если папка результатов ещё не настроена:

```text
Runtime\Core\Sessions\
Runtime\Debug\ModelTester\
```

## Файл профиля

Создать локальный файл профиля:

```text
%LOCALAPPDATA%\AI_HUB\user-profile.json
```

Минимальная структура:

```json
{
  "location": {
    "mode": "auto",
    "city": "",
    "region": "",
    "country": "",
    "countryCode": "",
    "timezone": "",
    "latitude": null,
    "longitude": null,
    "source": "ip",
    "updatedAt": ""
  }
}
```

## Формат журналов

Формат `jsonl`: одна строка = одно событие.

Примеры событий:

- `session_start`;
- `session_end`;
- `context_snapshot`;
- `user_message`;
- `assistant_message`;
- `task_started`;
- `debug_session_start`;
- `debug_user_message`;
- `debug_assistant_message`;
- `debug_log`.

У каждого события должно быть локальное время и UTC-время.

## Интеграция с моделью

- `llama-server` должен получать дополнительное скрытое `system`-сообщение с текущей датой, временем, часовым поясом и примерным местоположением, если оно известно.
- `llama-cli` fallback тоже должен получать этот контекст в prompt.
- Модель не получает доступ к файлам, интернету, shell или системным настройкам.

## Внешний сервис

- Для автоопределения IP-местоположения использовать HTTPS endpoint `https://ipwho.is/?lang=ru`.
- Запрос выполняется редко: при отсутствии сохранённого auto-местоположения.
- Если сервис недоступен, программа продолжает работать без местоположения.
- IP-местоположение считать приблизительным и не выдавать модели как точное.

## Реализация

- Добавить модели профиля пользователя и runtime-контекста.
- Добавить сервис профиля пользователя.
- Добавить сервис определения местоположения по IP.
- Добавить сервис построения скрытого контекста ядра.
- Добавить сервис `jsonl`-журналов с немедленной дозаписью событий.
- При запуске приложения создавать файл сессии ядра.
- При закрытии приложения писать `session_end`.
- При сохранении настроек результатов переносить новые сессии в выбранный results-root не нужно; текущая сессия остаётся там, где была создана при запуске.
- В debug-окне `F12` создавать отдельный debug-файл сессии.
- Записывать debug-сообщения пользователя, ответы модели и важные debug-логи.
- Повысить версию проекта.
- Обновить `REESTR.md` и `THIRD_PARTY_NOTICES.md` под внешний IP-сервис.
- Обновить историю и rollback-журнал.

## Проверки

- `dotnet build H:\AI_HUB\Исходники\AIHub\AIHub.csproj`
- scanner кириллицы;
- сверка ключей `ru.json` / `en.json`;
- запуск приложения и проверка создания файла сессии ядра;
- `F12` smoke-test и проверка создания отдельного debug-файла;
- проверка, что session/debug jsonl содержат корректный UTF-8 и валидные JSON-строки;
- проверка, что runtime/debug/session файлы не попадают в GitHub;
- установщик не собирать без отдельной команды пользователя.

## Не входит

- Ручный ввод местоположения в UI.
- Полная страница профиля пользователя.
- Реальный режим `Рассуждение / изучение`.
- Поиск/возврат к прошлым сессиям через UI.
- Публикация пользовательских сессий или debug-логов в GitHub.
