# ТЗ: парсер локального каталога Hugging Face

Дата: 2026-07-11

Статус: завершено; накопительная база и безопасное фоновое обновление реализованы

## Цель

Добавить в AI HUB проверяемый накопительный каталог публичных данных Hugging Face. На этом этапе компонент не подключается к ядру, сценариям, интерфейсу и автоматическому запуску основного приложения.

## Решение о составе каталога 2026-07-11

- исходный реестр содержит 11 направлений по 9 слотов: по 3 кандидата для лёгкого, оптимального и экстремального режима нагрузки;
- одна модельная семья может занимать слоты в нескольких направлениях, но в накопительном каталоге хранится одной записью;
- автоматический радар допускает только модели с подтверждённым числом параметров строго больше 8 миллиардов;
- полезные специализированные модели до 8B добавляются только как явные ручные исключения с зафиксированной ролью;
- квантования и сторонние упаковки не считаются новой модельной семьёй только из-за отдельного репозитория;
- посевной список не управляет выбором ядра; сценарий обращается к накопительной базе через отдельный `model_catalog_search`.

Направления: текст и знания; агенты и программирование; поиск и память; изображения; зрение и документы; видео; аудио и речь; данные и прогнозирование; наука и профессиональные задачи; пространственные задачи и робототехника; защита и контроль.

## Накопительная синхронизация

- при запуске диагностического режима `sync` проверяются все модели посевного реестра и все ранее найденные радаром модели;
- текущий каталог объединяется с прошлым состоянием, а не создаётся заново без истории;
- для записи сохраняются первая и последняя дата наблюдения, последняя успешная проверка, текущий и предыдущий revision SHA, число замеченных обновлений и доступность репозитория;
- изменения revision SHA и существенных metadata записываются в отдельный JSONL-журнал;
- недоступность отдельного репозитория не прерывает всю синхронизацию;
- Model Card и raw API сохраняются с SHA-256 как доказательная база.

## Радар популярных новинок

- радар не ограничивается списком известных разработчиков;
- первичный горизонт поиска — модели, созданные за последние 365 дней;
- источники кандидатов: верхние позиции Hub по trending, likes и downloads;
- автоматическое включение требует подтверждённого размера `>8B`, поддерживаемого направления и прохождения порога популярности;
- неизвестное число параметров, неполные metadata и модели `<=8B` остаются кандидатами ручной проверки, но не попадают в основной каталог автоматически;
- автор, которого нет среди авторов посевного списка, помечается как новый разработчик;
- на последующих запусках ранее найденные модели становятся обычными отслеживаемыми записями и проверяются на обновления.

## Результат этапа

- загрузчик получает публичные metadata через официальный Hugging Face Hub API;
- нормализатор преобразует ответы API в стабильную схему AI HUB;
- для каждой записи сохраняются ссылки на источник, время получения и SHA-256 сырого ответа;
- исходные JSON и Model Card сохраняются рядом с нормализованным каталогом;
- текст Model Card помечается как непроверенное описание автора;
- диагностический CLI позволяет выполнить ограниченный пробный сбор без запуска AI HUB;
- обнаружение не ограничено белым списком: поддерживаются поиск, произвольный автор и общая лента последних публичных моделей;
- список известных авторов в будущем может ускорять адресное обновление, но не блокирует появление новых разработчиков;
- unit-тесты проверяют разбор metadata, происхождение полей и устойчивость к неполным данным;
- отдельный живой прогон подтверждает совместимость с текущим публичным API.

## Данные карточки

- repo id, автор и SHA ревизии;
- даты создания и обновления;
- downloads/likes;
- pipeline, library, gated/private/disabled;
- лицензия и ссылка на неё;
- base model и тип связи;
- языки и датасеты;
- GGUF architecture, parameter count, context length и общий размер файлов, если API их сообщает;
- короткий фрагмент Model Card как `author_claim`, без выполнения или передачи ядру;
- предупреждения о неполных или противоречивых metadata;
- provenance: API URL, Model Card URL, локальные raw-файлы и их SHA-256.

## Хранение диагностического результата

```text
<output>/
  catalog.json
  raw/search.json
  raw/models/*.json
  raw/cards/*.md
```

## Ограничения этапа

- полный Hub автоматически не обходится: радар работает по ограниченным верхним выдачам официального API;
- синхронизация при старте добавляется отдельным фоновым сервисом с интервалом и защитой прежней базы;
- ядро получает только компактную выдачу отдельного инструмента, а не полный каталог;
- модели и другие файлы репозиториев не скачиваются;
- выводы о качестве модели по Model Card не делаются;
- приватные и gated-данные без авторизации не запрашиваются.

## Проверки

- Debug/Release build;
- unit-тесты парсера;
- format check;
- UTF-8 scanner;
- живой пробный сбор нескольких публичных репозиториев;
- ручное сравнение нормализованных полей с сохранённым raw JSON;
- smoke-запуск основного приложения.

## Расширение накопительного каталога 2026-07-11

- добавлен редактируемый посевной реестр `Каталоги/huggingface-catalog-seed.json`: 11 направлений, 99 слотов и 78 уникальных репозиториев;
- добавлены 12 явных ручных слотов-исключений для специализированных моделей, которым правило `>8B` не подходит;
- режим `sync` сохраняет накопительную базу schema v2, первую/последнюю дату наблюдения, доступность, предыдущий SHA и количество обновлений ревизии;
- изменения пишутся в `changes.jsonl`, а raw API и Model Card сохраняются с revision SHA в имени файла;
- сетевые запросы имеют ограничение размера, timeout, до трёх попыток при `429/5xx` и параллелизм не выше четырёх репозиториев;
- радар объединяет глобальные топы trending/likes/downloads и отдельные trending-выдачи всех поддерживаемых pipeline;
- радар требует публичный репозиторий, известный размер строго больше 8B, свежесть до 365 дней, поддерживаемый pipeline и порог популярности;
- чистые GGUF/GPTQ/AWQ/MLX/FP4/FP8 и другие quantized-упаковки автоматически не считаются новой моделью; содержательные fine-tune и distill допускаются;
- направления радара балансируются по pipeline, неизвестный автор помечается отдельно;
- первый живой sync создал накопительный каталог, повторный проход не создал дублей и показал неизменность всех отслеживаемых ревизий;
- после проверки политики итоговый живой каталог содержит 94 уникальные записи: 78 посевных и 16 найденных радаром, без недоступных репозиториев и предупреждений;
- каталог хранится локально в `Runtime/Каталоги/HuggingFace`, подключён к сценарию как отдельный tool и по-прежнему не имеет собственного UI.
- финальные проверки: Debug/Release build без ошибок и предупреждений, 28/28 тестов, `dotnet format --verify-no-changes`, UTF-8 scanner `303` файлов, локализации `329/329`, `git diff --check` и smoke-запуск основного приложения.
