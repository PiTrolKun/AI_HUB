# ТЗ: настройки хранилищ моделей и результатов

Дата: 2026-05-31

## Цель

Реализовать оставшиеся два пункта настройки стартового мастера AI HUB:

- `Хранилище моделей`;
- `Папка результатов`.

На этом этапе настройки только создаются, сохраняются и отображаются в интерфейсе. Подключать их к реальному скачиванию моделей, сохранению результатов или расчёту занятого места пока не нужно.

## Основное решение

Обе настройки работают по одному принципу:

- список одного или нескольких мест хранения;
- лимиты в ГБ;
- возможность временно превышать лимит;
- порядок мест хранения важен;
- после сохранения выбранное дублируется на главной странице.

## Выбор мест хранения

Для каждого пункта пользователь должен иметь возможность добавить одно или несколько мест хранения.

Добавление места хранения должно поддерживать два способа:

1. Через стандартный выбор папки Windows.
2. Через ручной ввод: пользователь может вставить путь или написать его текстом.

Хранить нужно не абстрактный диск, а конкретный адрес папки, например:

- `H:\AI_HUB\Models`;
- `D:\AI_HUB\Models`;
- `H:\AI_HUB\Results`;
- `D:\AI_HUB\Results`.

Не запрещать одинаковые диски или близкие пути между категориями. В будущем у каждой категории всё равно будет создаваться своя папка и своя логика использования.

## Порядок и приоритет

Порядок мест хранения важен.

- Первый адрес считается адресом по умолчанию.
- Остальные адреса считаются дополнительными.
- Позже, в местах где это понадобится, пользователь сможет выбрать конкретное место хранения вручную.

В интерфейсе настройки нужно прямо пояснить пользователю:

`Первый адрес используется по умолчанию. Остальные можно будет выбрать вручную там, где это потребуется.`

В первой реализации добавить кнопки изменения порядка:

- `Вверх`;
- `Вниз`.

## Лимиты

Все лимиты задаются в ГБ.

Для каждой категории (`Хранилище моделей`, `Папка результатов`) нужно хранить:

- общий лимит категории в ГБ;
- включено ли временное превышение лимита;
- размер временного превышения в ГБ;
- лимит для каждого отдельного места хранения в ГБ.

Временное превышение также задаётся в ГБ, не в процентах.

Примеры:

- общий лимит моделей: `300 ГБ`;
- временное превышение моделей: `+20 ГБ`;
- лимит одного адреса моделей: `200 ГБ`;
- общий лимит результатов: `100 ГБ`;
- временное превышение результатов: выключено.

## Главная страница

После настройки пункт 1 и пункт 2 на главной странице должны показывать выбранное пользователем.

Пункт `Хранилище моделей` должен показывать:

- сколько мест хранения настроено;
- адрес по умолчанию;
- дополнительные адреса, если они есть;
- общий лимит;
- временное превышение.

Пример:

`Настроено: 2 места. По умолчанию: H:\AI_HUB\Models. Дополнительно: D:\AI_HUB\Models. Общий лимит: 300 ГБ. Временное превышение: +20 ГБ.`

Пункт `Папка результатов` должен показывать:

- сколько мест хранения настроено;
- адрес по умолчанию;
- дополнительные адреса, если они есть;
- общий лимит;
- временное превышение.

Пример:

`Настроено: 1 место. По умолчанию: D:\AI_HUB\Results. Общий лимит: 100 ГБ. Временное превышение: выключено.`

Если адресов много, на главной странице можно показывать адрес по умолчанию, 1-2 дополнительных адреса и количество остальных.

## Файл настроек

Настройки хранения сохранить отдельным JSON-файлом вне исходников проекта:

`%LOCALAPPDATA%\AI_HUB\storage-settings.json`

`state.json` оставить для общего состояния приложения.

Предлагаемая структура:

```json
{
  "models": {
    "totalLimitGb": 300,
    "allowTemporaryOverflow": true,
    "temporaryOverflowGb": 20,
    "locations": [
      {
        "path": "H:\\AI_HUB\\Models",
        "limitGb": 200
      },
      {
        "path": "D:\\AI_HUB\\Models",
        "limitGb": 100
      }
    ]
  },
  "results": {
    "totalLimitGb": 100,
    "allowTemporaryOverflow": false,
    "temporaryOverflowGb": 0,
    "locations": [
      {
        "path": "H:\\AI_HUB\\Results",
        "limitGb": 100
      }
    ]
  }
}
```

## Интерфейс страницы настройки

На странице настройки внутри основного окна AI HUB нужно добавить секции:

1. `Хранилище моделей`.
2. `Папка результатов`.

Для каждой секции:

- список адресов хранения;
- поле ручного ввода пути;
- кнопка выбора папки через Windows;
- кнопка добавления адреса;
- кнопка удаления адреса;
- кнопки `Вверх` / `Вниз`;
- поле лимита для выбранного адреса в ГБ;
- общий лимит категории в ГБ;
- переключатель временного превышения;
- поле временного превышения в ГБ.

На этом этапе допустимо сделать интерфейс простым, но он должен быть понятным и рабочим.

## Что пока не делаем

- Не скачиваем модели.
- Не создаём реальные файлы моделей.
- Не переносим результаты.
- Не считаем фактически занятое место.
- Не применяем лимиты к реальным операциям.
- Не блокируем одинаковые диски/папки между моделями и результатами.
- Не делаем автоматическое распределение файлов по дискам.
- Не делаем полноценную проверку прав записи в выбранные папки, если это усложнит задачу.

## Версия

После реализации повысить версию с `0.0.8-dev` до `0.0.9-dev`.

## Проверки

- `dotnet build`;
- `Инструменты/check-cyrillic-integrity.ps1`;
- запуск приложения;
- проверить, что страница настройки открывается внутри основного окна;
- проверить, что для моделей можно добавить путь через ручной ввод;
- проверить, что для результатов можно добавить путь через ручной ввод;
- проверить, что кнопка выбора папки Windows доступна;
- проверить, что можно добавить несколько адресов;
- проверить, что порядок адресов можно менять кнопками `Вверх` / `Вниз`;
- проверить, что можно удалить адрес;
- проверить, что сохраняются общий лимит, лимиты адресов и временное превышение;
- проверить, что создаётся `%LOCALAPPDATA%\AI_HUB\storage-settings.json`;
- проверить, что пункт 1 и пункт 2 на главной странице показывают выбранные адреса и лимиты;
- проверить, что кнопка `Назад` возвращает на главную страницу;
- проверить, что окно не падает при переключении темы.
