# ТЗ: реестр возможностей и Hugging Face provider

Дата создания: 2026-06-01

## Цель

Сделать следующий слой AI_HUB: ядро должно не ждать, что пользователь попросит конкретную модель, а само понимать, каких возможностей не хватает для задачи, и уметь подобрать кандидатов через структурированный каталог Hugging Face.

Основная мысль: Qwen3 8B остаётся лёгким ядром-диспетчером и бытовым собеседником. Специализированные действия выполняют отдельные сценарии, инструменты и модели.

## Правило внедрения новых сценариев

Каждый новый сценарий должен описывать:

- какую задачу пользователя он решает;
- какие возможности ему нужны;
- какие модели, backends, инструменты или папки должны быть установлены;
- как проверить, что они уже есть;
- что делать, если их нет;
- как предложить пользователю докачать недостающий компонент;
- как зарегистрировать компонент после установки;
- какие ограничения безопасности и лицензий есть.

Ядро не должно само угадывать всё из воздуха. Оно получает состояние системы и вызывает инструменты, которые возвращают факты.

## Минимальные роли возможностей

На первом шаге завести роли:

- `core` — основное ядро общения и диспетчеризации;
- `web_search` — поиск информации в интернете;
- `web_download` — скачивание файлов по ссылке;
- `reranker` — улучшение выбора найденных web-результатов;
- `embedding` — embeddings для будущего RAG и поиска по документам.

В будущем добавить:

- `ocr`;
- `vision`;
- `speech_to_text`;
- `text_to_speech`;
- `image_generation`;
- `video`.

## Installed Inventory

Программа должна уметь собрать текущее состояние:

- какие роли уже установлены;
- где лежит модель или инструмент;
- какой manifest найден;
- формат модели;
- статус проверки;
- можно ли запускать в F12;
- каким backend-ом пользоваться;
- каких ролей не хватает.

Сейчас частично есть:

- `core-model.json`;
- `tool-model.json`;
- discovery моделей в F12.

Нужно привести это к более общему виду.

## Task Planner в F12

Добавить debug-проверку, где пользователь вводит обычную задачу, а ядро/планировщик возвращает структурный план:

- тип задачи;
- нужные роли;
- что уже установлено;
- чего не хватает;
- какой следующий инструмент нужен;
- можно ли продолжать без скачивания;
- нужно ли предложить пользователю докачать компонент.

В F12 подтверждение скачивания пока не нужно. Это лаборатория.

## Hugging Face provider

Добавить инструмент, который работает не через HTML, а через Hugging Face API.

Минимальные команды:

```text
hf_find_model: role=embedding max_size=1GB format=gguf license=apache-2.0
hf_model_files: Qwen/Qwen3-Embedding-0.6B-GGUF
```

Инструмент должен возвращать структурированные факты:

- repo id;
- автор/организация;
- назначение/теги;
- лицензия;
- дата обновления;
- downloads/likes, если доступны;
- список подходящих файлов;
- размер файлов;
- прямые `resolve` ссылки;
- предупреждения, если лицензия/размер/формат не подходят.

Цель: ядро выбирает из таблицы фактов, а не блуждает по web-страницам.

## Подбор модели

Будущий боевой сценарий:

1. Пользователь ставит обычную задачу.
2. Ядро определяет, какая возможность нужна.
3. Inventory сообщает, что нужной роли нет.
4. Hugging Face provider подбирает кандидатов.
5. Ядро выбирает лучший вариант и объясняет простым языком.
6. В боевом UI пользователь подтверждает скачивание.
7. AI_HUB скачивает, проверяет и регистрирует модель.
8. Задача продолжается.

На этом ТЗ подтверждение и боевой UI не делать, только F12/инструментальный слой.

## Ограничения

- Не удалять скачанные модели.
- Не скачивать новую модель без явной команды в debug-режиме или будущего подтверждения в UI.
- Не публиковать модели, runtime и пользовательские результаты в GitHub.
- Не добавлять установщик без прямой команды пользователя.
- Не заменять текущий web-search; Hugging Face provider отдельный инструмент.

## Проверки

- `dotnet build H:\AI_HUB\Исходники\AIHub\AIHub.csproj`
- scanner кириллицы;
- сверка `ru.json` / `en.json`, если появятся UI-строки;
- F12 smoke-test `hf_find_model` для роли `embedding`;
- проверка, что provider возвращает размеры и прямые ссылки;
- проверка, что скачивание не запускается само по себе;
- установщик не собирать без отдельной команды пользователя.

## Ожидаемый результат

- У AI_HUB появляется первый реестр возможностей.
- У AI_HUB появляется inventory установленных ролей.
- F12 умеет показать, чего не хватает для задачи.
- Hugging Face API становится основным источником подбора моделей.
- Ядро получает структурированные данные для выбора модели, а не HTML.
